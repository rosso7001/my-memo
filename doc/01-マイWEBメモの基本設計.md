# マイWEBメモ 基本設計

## 1. 概要

どこからでも（PC / スマホ / 各種ブラウザ）アクセス・参照・更新できる個人用メモ帳。  
GitHub の機能だけで完結するシンプルな構成とする。

---

## 2. システム構成

```
ブラウザ
  │
  │ ① ページを開く
  ▼
GitHub Pages（フロントエンド配信）
  │ HTML / CSS / JS を返す
  ▼
ブラウザ（画面が構成される）
  │
  │ ② 追加・編集・削除
  │    Authorization: Bearer [localStorageのTOKEN]
  ▼
GitHub API
  │ data/202611.md を読み書き（= commit/push 相当）
  ▼
my-memo-data リポジトリ（データ専用・Private）
  └── data/
      ├── 202611.md
      └── 202612.md  ← 月が変わったら新規作成
```

### 役割分担

| 役割 | 担当 |
|---|---|
| 画面配信 | GitHub Pages |
| 画面描画・操作・ロジック | ブラウザ（JS） |
| MD レンダリング | marked.js（CDN） |
| 音声認識（STT） | Web Speech API（ブラウザ内蔵・スマートフォン専用、PC は対象外） |
| TOKEN 保管 | localStorage（Fine-grained PAT） |
| データ読み書き | GitHub API（GET / PUT / DELETE） |
| データ永続化 | my-memo-data リポジトリ（data/YYYYMM.md） |

---

## 3. ファイル構成

### リポジトリ構成

```
my-memo/                      ← ソース管理（Public）※ GitHub Pages で公開
├── index.html                ← ルートに配置（GitHub Pages の公開対象）
├── frontend/                 ← フロントエンド資材
│   ├── style.css
│   └── js/
│       ├── app.js            ← 画面描画・UIイベント
│       ├── api.js            ← API呼び出し口（将来の差し替えポイント）
│       └── memo.js           ← MDパース・操作ロジック
└── backend/                  ← バックエンド資材（フェーズ2で追加・今は空）

my-memo-data/                 ← データ専用（Private）
└── data/
    ├── 202611.md             ← 年月単位のメモデータ
    └── 202612.md             ← 月が変わったら新規作成
```

### frontend/ 各ファイルの役割

| ファイル | 役割 |
|---|---|
| index.html | 画面構造（ルート直下に配置） |
| frontend/style.css | スタイル（marked.js が生成した HTML タグに適用） |
| frontend/js/app.js | 画面描画・UIイベント処理 |
| frontend/js/api.js | GitHub API 呼び出し（フェーズ2でバックエンドへの呼び出しに差し替え） |
| frontend/js/memo.js | MD のパース・エントリ操作ロジック |

### GitHub Pages 設定

- 公開ディレクトリ：ルート（`/(root)`）を指定
- GitHub Pages の無料プランでは `/frontend` 等の任意フォルダを指定できないため、`index.html` をルートに配置して対応

## 4. データ形式（YYYYMM.md）

### ファイル管理

- **ファイル名**：`YYYYMM.md`（例：`202611.md`）
- **単位**：年月単位で1ファイル
- 月が変わったら新しいファイルを作成する（画面のプルダウンで自動的に切り替わる）

### 構造

```markdown
### 20261125090000
一番新しいメモ内容

### 20261124143022
ひとつ前のメモ内容
AAA
BBB
CCC

### 20261124090000
最初のメモ
```

### ルール

- `### yyyymmddhhmmss` が1エントリのヘッダー（追加時に JS が自動生成）
- 新しいエントリは**先頭に差し込む**（上が新しい）
- `### 日時` から次の `### 日時` までが削除・編集の単位
- 編集しても日時タグは変えない

## 5. 画面構成

```
┌─────────────────────────────────────┐
│  My Memo                            │
├─────────────────────────────────────┤
│  [2026年11月 ▼]                     │
├─────────────────────────────────────┤
│  [入力エリア（複数行）]               │  ← 当月選択時のみ表示
│                        [🎤] [追加]  │  ← 当月選択時のみ表示
├─────────────────────────────────────┤
│  2026/11/25 09:00:00  [編集] [削除] │
│  一番新しいメモ内容                  │
├─────────────────────────────────────┤
│  2026/11/24 14:30:22  [編集] [削除] │
│  ひとつ前のメモ内容                  │
│  AAA                                │
│  BBB                                │
│  CCC                                │
├─────────────────────────────────────┤
│  [ファイルマージ]                    │  ← 過去月選択時のみ表示
└─────────────────────────────────────┘
```

- 上部：年月プルダウン（固定）+ 入力エリア・マイクボタン・追加ボタン（**当月選択時のみ表示**）
- 下部：エントリ一覧（新しい順）、各エントリに編集・削除ボタン
- 一覧最下部：ファイルマージボタン（**過去月選択時のみ表示**）
- MD は marked.js でレンダリングして表示
- 見た目は CSS でカスタム

## 6. 操作仕様

### 追加

- **当月のファイルを選択中のみ操作可能**（過去月は入力エリア・追加ボタン自体を非表示）

**テキスト入力の場合**

```
① 入力エリアにテキストを入力
② [追加] ボタンを押す
③ JS が現在日時（yyyymmddhhmmss）を生成
④ 当該年月の YYYYMM.md の先頭に「### 日時 + 入力内容」を差し込む
⑤ GitHub API PUT で保存
⑥ 画面を再描画
```

**音声入力の場合**（※スマートフォン専用。PC ではマイクボタンは表示されない）

```
① [🎤] ボタンを押す（Web Speech API が起動・認識中は赤く点滅）
② 話した内容がリアルタイムで入力エリアに追記される
③ [⏹️] ボタンを押して音声認識を停止
④ あとはテキスト入力と同様に [追加] ボタンで保存
   ※ ?mic=1 のURL引数付きでアクセスすると最初からマイクON状態で起動する
```

### 編集

```
① [編集] ボタンを押す
② 該当エントリの本文がテキストエリアに展開される
③ 内容を修正して [保存] を押す
④ 日時タグはそのままで本文だけ書き換え
⑤ GitHub API PUT で保存
⑥ 画面を再描画
```

### 削除

```
① [削除] ボタンを押す
② 該当エントリ（### 日時 〜 次の ### 日時 の直前）をまるごと除去
③ GitHub API PUT で保存
④ 画面を再描画
```

### ファイルマージ

- **過去月のファイルを選択中のみ操作可能**（当月は「ファイルマージ」ボタン自体を非表示）

```
① [ファイルマージ] ボタンを押す
② 確認ダイアログを表示（マージ元・マージ先のファイル名を明示）
③ マージ先を特定する（現在ファイルより未来で最も近い年月のファイル）
④ マージ先・マージ元の内容を GitHub API GET で取得
⑤ [マージ先エントリ] + [マージ元エントリ] の順で連結する
   ※ 各ファイル内は降順保証済みのため、ソートは不要
⑥ 連結した内容を GitHub API PUT でマージ先ファイルに上書き保存
⑦ マージ元ファイルを GitHub API DELETE で削除
⑧ 年月プルダウンを再構築し、マージ先ファイルへ切り替える（マージ結果をすぐ確認できる）
```

## 7. TOKEN 設定

- 初回のみ設定画面（または prompt）で PAT を入力
- localStorage に保存
- Fine-grained PAT で対象リポジトリの Contents のみ読み書き権限に絞る

## 8. 採用ライブラリ

| ライブラリ | 用途 | 読み込み方法 |
|---|---|---|
| marked.js | MD → HTML 変換 | CDN（1行） |
| Web Speech API | 音声 → テキスト変換（音声入力） | ブラウザ内蔵（追加ライブラリ不要）スマートフォン専用、PC は対象外 |

## 9. 開発ワークスペース構成

作業ワークスペースのルートパスは環境によって異なる（例：`c:\rosso7001\work-202611\` など）。
以下はルート配下の相対構成として読むこと。

```
{ワークスペースルート}\
├── src\                        ← 既存の独立バッチ群
├── doc\                        ← 設計書類（既存分・web系以外）
├── my-memo\                    ← Webシステム ソース ※別途 GitHub リポジトリへ手動 push
│   ├── index.html              ← ルートに配置（GitHub Pages の公開対象）
│   ├── doc\                    ← 設計書（本ファイルもここ）
│   │   ├── 01-マイWEBメモの基本設計.md
│   │   └── archive\            ← 調査メモ等
│   ├── frontend\
│   │   ├── style.css
│   │   └── js\
│   │       ├── app.js          ← 画面描画・UIイベント
│   │       ├── api.js          ← API呼び出し口（将来の差し替えポイント）
│   │       └── memo.js         ← MDパース・操作ロジック
│   └── backend\                ← 空（フェーズ2で追加）
└── my-memo-data\               ← データ専用 ※別途 GitHub リポジトリへ手動 push
    └── data\
        ├── 202611.md           ← 年月単位のメモデータ
        └── 202612.md           ← 月が変わったら新規作成
```

### GitHub への反映

| ディレクトリ | GitHub リポジトリ | push 方法 |
|---|---|---|
| `my-memo\` | my-memo | 手動 push |
| `my-memo-data\` | my-memo-data | 手動 push |
| `src\` `doc\` | （このワークスペースのリポジトリ） | 手動 push |
