# 個人用メモ・日記Webシステム（Google Keep風）構築メモ

## 1. 要件・前提条件
* **用途**：個人用のメモ・日記管理（Google Keepのような仕組み）
* **規模**：1人利用、データ容量は数MB〜10MB程度
* **開発スタイル**：JS / TypeScript / Python を中心に、AIを活用して超軽量に構築する

---

## 2. サーバーレス構成の基本イメージ

### 従来のサーバー構成との違い
* **従来のWeb/APサーバー（Tomcatなど）**：
  * サーバープロセスを常時立ち上げて待機させ、そこに資材を配置（デプロイ）する。
  * OSやプロセスの管理・監視が必要。
* **サーバーレス / BaaS構成**：
  * 自分でAPサーバーを常時起動しておく必要はない。
  * 画面ファイルや処理関数をクラウド側へ配置しておき、**リクエストが来た瞬間だけ処理が起動**して応答する。
  * 状態（セッションなど）をメモリに持たず、データは毎回DBへ読み書きする（ステートレス設計）。

### 役割分担（3つの専用機能の組み合わせ）
サーバーを3台借りるのではなく、役割ごとのマネージド機能を組み合わせて利用する。
1. **フロントエンド（画面）**：HTML / CSS / JS(TS) などの静的ファイルを配信する場所
2. **バックエンド（処理・API / 認証）**：リクエスト時だけ動くサーバーレス関数や認証機能
3. **データベース（DB）**：メモのタイトル・本文・更新日時・タグなどを保存する場所

---

## 3. 採用候補となる構成（無料枠・超軽量）

### 第一候補：Cloudflare 完結構成
* **構成**：`Cloudflare Pages`（画面） + `Cloudflare Workers`（API） + `Cloudflare D1`（SQLiteベースDB）
* **特徴**：
  * フロント・API・DBを1つのプラットフォーム内でまとめやすい。
  * 10MB程度の個人利用なら容量・リクエスト数ともに無料枠内で十分運用可能。
  * スリープによる長期停止の煩わしさが少ない。

### 代替候補：フロント + Supabase 構成
* **構成**：`Cloudflare Pages / Vercel`（画面） + `Supabase`（PostgreSQL / 認証）
* **特徴**：
  * DBと認証機能が最初から揃っている。
  * **注意点**：無料枠では約1週間アクセスがないとプロジェクトが一時停止する仕様があるため、数日おきに開く用途では再開の手間が発生する場合がある。

---

## 4. 設計・運用時のポイント
* **最小構成から始める**：まずは「タイトル・本文・更新日時・検索・ピン留め」程度に絞り、DBテーブルも1〜2個でシンプルに作る。
* **認証（アクセス制限）を必ず入れる**：外部公開URLから第三者が閲覧・編集できないよう、ログイン認証やトークン認証を最初に組み込む。
* **バックアップ機能を用意する**：無料枠の仕様変更や停止リスクに備え、全データをJSONやMarkdown形式でエクスポートできる機能を付けておく。
