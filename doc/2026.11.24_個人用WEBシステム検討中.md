# 個人用WEBシステム検討まとめ（2026.11.24時点）

## 1. 作りたいもの

- どこから（PC / スマホ / 各種ブラウザ）でもアクセス・参照・更新できるメモ帳
- Google Keep で代替できるが、**完全に自分用にカスタムしたものを作りたい**
- 将来的にカレンダー・日記機能への拡張も視野に入れる

---

## 2. 方針・前提

- 新しいサービスの契約・登録は極力しない
- 既に日常的に使っている **GitHub だけで完結** させる（シンプルさ優先）
- 個人用途（1人利用）のため、スケールや冗長性は不要
- バックエンドサーバーは持たない（インフラ管理ゼロ）

---

## 3. 採用構成（フェーズ1）

### GitHub 完結構成（localStorage パターン）

```
ブラウザ
  │
  │ ① ページを開く
  ▼
GitHub Pages（フロントエンド配信）
  │ HTML / CSS / JS を返す
  ▼
ブラウザ（画面が構成される）
  │
  │ ② メモ読み書き
  │    Authorization: Bearer [localStorageのTOKEN]
  ▼
GitHub API（バックエンド代わり）
  │ .md ファイルを返す / 保存する（= commit/push 相当）
  ▼
GitHub Private リポジトリ（データ層）
  └── data/
      ├── 20261124.md
      └── 20261125.md  ← メモデータ
```

### 役割分担

| 役割 | 担当 | 備考 |
|---|---|---|
| 画面配信 | GitHub Pages | HTML/CSS/JS を配信 |
| 画面描画・操作 | ブラウザ（JS） | ロジックもここに書く |
| TOKEN 保管 | localStorage | 初回のみ手動設定 |
| データ読み書き | GitHub API | git コマンドの HTTP 版 |
| データ永続化 | GitHub Private Repo（.md） | commit/push と同じ結果 |

---

## 4. 技術的な整理

### GitHub API とは
- 普段ターミナルで打っている git コマンドを HTTP リクエストで行うもの
- `git push` → `PUT /contents/ファイル名` と同じ結果になる
- コミット履歴も自動で残る

### TOKEN（Personal Access Token）について
- 普段 `git push` で使っているアクセストークンと同じもの
- JS に直書きすると F12 開発ツールで誰でも見えてしまうため NG
- **localStorage に保存する**（自分専用ツールとして割り切り）
- Fine-grained PAT で対象リポジトリ・最小権限に絞ること

### なぜ JS 直書きが NG か
- URL が世の中に存在する = 誰でもアクセス可能
- 「自分しか知らない URL」はセキュリティの担保にならない（Security by obscurity）
- localStorage ならブラウザ内に保持され、他人のブラウザからは見えない

---

## 5. データ管理方針

- **保存形式**：Markdown ファイル（.md）
- **ファイル単位**：年単位で1ファイル（書き込みは1日1件あるかないかの程度のため）
- **ファイル名**：`YYYY.md`（例：`2026.md`）
- メモの内容はプレーンテキスト中心
- コミット履歴がそのまま更新履歴になる

## 6. 将来の拡張候補（フェーズ2）

バックエンドで何かしらの処理が必要になった時点で以下の2候補を検討する。
**今の時点では決めない。どんなロジックが必要になったかを見てから選ぶ。**

### 構成イメージ（共通）

```
ブラウザ  ──→  バックエンド（Workers or Functions）  ──→  GitHub API
```

---

### 候補A：Cloudflare Workers

```
ブラウザ  ──→  Cloudflare Workers  ──→  GitHub API
```

| 項目 | 内容 |
|---|---|
| 無料枠 | 月10万リクエスト/日・スリープなし |
| 言語 | JS / TS のみ |
| GitHub 連携 | push で自動デプロイ可 |
| 特徴 | フロントも Cloudflare Pages に移行すれば全部 Cloudflare で完結 |
| 注意 | Python は書けない |

---

### 候補B：Vercel Functions

```
ブラウザ  ──→  Vercel Functions  ──→  GitHub API
```

| 項目 | 内容 |
|---|---|
| 無料枠 | 月100GB転送・スリープなし |
| 言語 | JS / TS / Python など複数対応 |
| GitHub 連携 | ◎ 最も自然（push で自動デプロイ） |
| 特徴 | GitHub との親和性が高く移行しやすい |
| 注意 | フロントも Vercel に移行が必要（GitHub Pages は使えなくなる） |

---

### 選択の目安

| こうなったら | 選択 |
|---|---|
| JS/TS で完結できる・全部統一したい | Cloudflare Workers |
| Python でロジックを書きたい | Vercel Functions |
| GitHub との連携を最優先にしたい | Vercel Functions |

### 段階的移行の考え方
- フロントの画面はほぼそのまま流用可能
- ブラウザ ↔ GitHub API の呼び出し部分を、ブラウザ ↔ バックエンド ↔ GitHub API に差し替えるだけ
